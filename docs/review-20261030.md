# MoonCard：APDU交易日志的离线回归检查工具

账号：btlqql。主要语言：MoonBit。许可：Apache-2.0。修订日期：2026-10-30。

## 应用场景与实际价值

**场景一：终端应用选择逻辑回归。** 终端程序修改应用选择逻辑后，开发者导出`>>`命令／`<<`响应的APDU日志，以MoonCard读取PPSE候选AID、选中的AID与卡片返回的DF Name，定位选择不一致及错误命令顺序。无需连接读卡器，复现材料是可共享的文本日志。

**场景二：EMV交易脚本排错。** 开发者需要判断READ RECORD是否覆盖GPO给出的AFL，以及GENERATE AC输入是否满足记录中的CDOL1长度。工具维护应用上下文，输出问题代码、步骤号和原因，避免只逐条解码APDU却看不到前后步骤的约束。

**场景三：测试流水线的失败日志筛查。** `session`在发现`fail`时返回退出码1；正常或需要人工复核的日志分别显示`pass`、`review`，后者退出码为0。可把日志分析加入已有测试脚本，进一步按业务规则处理review。PAN展示使用掩码；自动化并不代表EMV认证。

## 已实现的处理链

日志读取 → 短／扩展APDU解析 → BER-TLV递归解析 → PPSE候选及AID一致性检查 → GPO/AFL解析 → AFL记录访问与完整性检查 → 汇总记录中的PAN、有效期与CDOL1 → GENERATE AC长度检查 → 带原因的报告及退出码。

本轮修复了失败响应仍推进交易状态、重选应用沿用旧AFL／记录／CDOL、缺失响应吞掉下一条命令、空日志误判通过的问题。PAN与有效期按应用记录集合检查，不再要求每条记录重复携带这些字段。日志解析错误和孤立响应会形成失败报告。

## 可复现案例

在项目根目录运行：

```sh
moon run cmd/main --target js -- session examples/sessions/happy.log
moon run cmd/main --target js -- session examples/sessions/unread-afl.log
moon run cmd/main --target js -- session examples/sessions/failed-gpo.log
```

实际结果：`happy.log`为pass／退出0；`unread-afl.log`报告`AFL_RECORD_MISSING`／退出1；`failed-gpo.log`报告`STATUS_ERROR`，AFL仍为0／退出1。样例为作者构造的测试数据，未使用真实终端交易证明应用效果。

## 当前实现边界

这是离线交易脚本检查器。未连接PC/SC、NFC或真实读卡器；不实现ARQC/MAC、PIN、证书验签、EMV风险管理或Level 3认证。`pass`只表示已实现规则未发现问题，不表示交易被银行批准、密码学正确或通过EMV认证。只支持已记录的请求与响应；不是完整EMV协议实现。
